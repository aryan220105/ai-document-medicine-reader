# FormSathi knowledge base

Synthetic demonstration guidance only. Not official government, bank, insurer, or school
instructions. Seed the vector store with `python scripts/seed_knowledge_base.py`.

## Files

| File | What it holds | Generated by |
| --- | --- | --- |
| `forms/*.json` | The seeded known forms, with fingerprint terms and per-field guidance | `scripts/_write_knowledge.py` |
| `common_fields.json` | The multilingual common-field dictionary: 56 fields, 927 printed wordings across English, Hindi, Kannada, and Urdu | `scripts/build_field_dictionary.py` |
| `label_patterns.json` | Fallback heuristics that describe the *shape* of an answer when no field matches | `scripts/build_field_dictionary.py` |

**Do not hand-edit `common_fields.json` or `label_patterns.json`.** Edit the readable
sources in `scripts/field_dictionary/` and regenerate, so that the four language columns
for a field stay side by side and a reviewer can see at a glance when one is missing. The
generator refuses to write if any field lacks one of the four languages.

## Dictionary entry shape

```json
{
  "id": "date_of_birth",
  "type": "date",
  "aliases": { "en": ["date of birth", "dob"], "hi": ["जन्म तिथि"], "kn": ["ಜನ್ಮ ದಿನಾಂಕ"], "ur": ["تاریخ پیدائش"] },
  "keywords": { "en": ["birth"], "hi": ["जन्म"], "kn": ["ಜನ್ಮ"], "ur": ["پیدائش"] },
  "simple_label":   { "en": "…", "hi": "…", "kn": "…", "ur": "…" },
  "what_to_enter":  { "en": "…", "hi": "…", "kn": "…", "ur": "…" },
  "why_needed":     { "en": "…", "hi": "…", "kn": "…", "ur": "…" },
  "example": "15/08/1998",
  "format_hint": { "en": "DD/MM/YYYY", "…": "…" },
  "validation": { "kind": "date", "format": "DD/MM/YYYY" },
  "priority": 1.1
}
```

- `aliases` are the printed wordings a form might actually use, in that language's own
  script. They are matched after a script-aware fold that removes case, combining marks,
  and Arabic letter variants, so one alias covers several spellings and survives a noisy
  scan.
- `keywords` are single distinguishing words, used only as a weak last resort below the
  alias layers.
- `validation.kind` selects a checker in `app/services/validation_service.py` and is what
  gives an unknown form's field a working answer box.
- `priority` nudges a row above its competitors when two could match; keep it near 1.0.

## Adding a field

1. Add an `entry(...)` to the right module in `scripts/field_dictionary/`.
2. Fill all four languages. Write Hindi in Devanagari, Kannada in Kannada script, and Urdu
   in Arabic script — never transliterated into Latin letters. A romanised string is not a
   translation and reads as a failure to the person who needs that column.
3. Run `python scripts/build_field_dictionary.py`.
4. Run `pytest tests/test_unknown_forms.py`, which asserts that every field covers all
   four languages and that each column is written in the expected script.
5. Re-seed the vector store if you want retrieval to see the new row.

## Chunking

One chunk per field per language, for both the known forms and the common dictionary.
Indexing the dictionary is what gives retrieval anything to say about an unknown form;
without it the vector store only knows the seeded demo forms.
